Notes and sources

Checked on 30 September 2026 against each product's own documentation.

macOS

Dock › Options › Assign To pins a whole app, not a window, to the desktop you are on; you cannot choose a desktop by number, and a new window follows only its app's assignment. Mission Control shows one desktop's windows at a time and a drag there is a one-off move. Shortcuts has Move Window and Resize Window actions, but there are no rules to trigger.

Rectangle Pro

Layout entries match by title and can apply when a window opens or when a chosen display connects or disconnects. Those are triggers per display event, not setups stored side by side. It does not move windows between desktops.

Sources

  • layouts
  • URL scheme

Moom 4

Saved layouts are snapshots: windows are matched by title only when a layout is applied, the geometry is the saved frame, and a window opened later is not routed. Layouts can trigger on a display configuration. Several named layouts exist, but no profiles that group rules.

Sources

  • custom actions
  • AppleScript

Stay

Stores window frames per display combination and restores them when displays change; titles are matched with regular expressions. Windows are restored when their app launches, but a window opened later in a running app is not routed. The stored sets follow the display setup; there are no profiles you switch yourself. Automation is basic AppleScript and hot keys.

ShiftPlus

A workspace is restored by hotkey: apps are launched on their assigned Space, and an app already on the wrong Space is quit and relaunched after asking; open windows are not moved. Arrangement presets are per app, applied on restore. Automation is a Raycast extension.

yabai

Rules match titles by regular expression and send windows to a Space with a grid position. Moving windows between Spaces works with System Integrity Protection on since 7.1.25 (May 2026) on recent macOS; older systems need the scripting addition. Display signals fire, but re-placing is a script you write. --one-shot rules apply once to the next matching window; they are not tied to one window. Everything is configured from the command line.

Sources

  • manual

AeroSpace

Uses its own virtual workspaces instead of native desktops. on-window-detected rules match titles and run for every new window, in a TOML config. Workspaces are re-assigned to monitors on reconnect; single windows are not re-placed. Rules choose tiling or floating, not a size or position (#714). Binding modes switch key sets, not window rules.

Sources

Hammerspoon

A scripting framework: every “partly” mark means "possible if you write the Lua". Nothing here works out of the box, and moving windows between Spaces is reported unreliable on macOS 15 and later in released builds (#3889).
